## 0. 一次性准备（约 5 分钟，做完保持窗口不关）

**0.1 确认核心可用**——打开 Git Bash，逐行粘贴：

```bash
vision-relay status --json
```

✅ 预期：输出一串 JSON，且 `"ok": true`（服务是否运行无所谓）。
❌ 若提示“找不到命令”：说明核心不在 PATH，先停下（R6 之后的用例都无法做）。

**0.2 启动 GUI（开发模式）**——新开一个 Git Bash 窗口，逐行粘贴：

```bash
cd /e/LLMproject/Github/vision-relay/gui
pnpm tauri dev
```

✅ 预期：等待编译（首次可能 1–3 分钟），弹出标题为 **vision-relay 控制台** 的桌面窗口。
⚠️ 这个黑窗口（终端）全程不要关——关了 GUI 就退了。

**0.3 打开视觉对照稿**——再开一个 Git Bash 窗口粘贴：

```bash
start /e/LLMproject/Github/vision-relay/docs/superpowers/specs/gui-mockups/index.html
```

✅ 预期：浏览器打开 mockup 页（注意：它顶部的标签页是**文档目录**，不是软件界面）。

**0.4 检查托盘图标**——Windows 任务栏右下角（可能收进 `^` 折叠区）应出现一个 👁 图标。找不到就点 `^` 展开。

## R1 关闭确认：「仅关界面」并记住（对应 G10）

1. 记下当前总览页顶部圆点颜色（绿=服务运行中；如果没开路由，先点一下滑动开关把它打开，等圆点变绿）。
2. 点 GUI 窗口右上角 **✕**。
3. ✅ 弹出对话框「**关闭 vision-relay 控制台？**」。
4. 勾选「**记住我的选择**」。
5. 点「**仅关闭界面（服务继续）**」。
6. ✅ 窗口消失；任务栏托盘的 👁 图标还在。
7. 回到 Git Bash 粘贴：

```bash
vision-relay status
```

✅ 预期输出：`running (pid 数字)` ——服务确实还在跑。

8. 双击托盘 👁 图标 → ✅ 窗口重新弹出。
9. 再点一次 **✕** → ✅ **直接隐藏、不再弹对话框**（记住选择生效）。

**恢复（可选，想重新测弹窗时才需要）**：在 GUI 窗口按 `F12` 打开 DevTools → Console 标签 → 粘贴 `localStorage.removeItem("vr.close")` 回车 → 关闭 DevTools。

## R4 设置页：脏指示与「切页即丢弃」（对应 G11）

> 已知行为（不是 bug，2026-08-23 裁决选项①）：**未保存的修改在切换页面后会被丢弃**。
> 页底文案「输入类修改统一由这里保存生效」即此含义——切页前记得点保存。

1. 左侧导航点「**设置**」。
2. 在「模型名称」输入框末尾随便加一个字符（比如加个 `x`）。
3. ✅ 页面底部立刻出现「**● 1 处未保存修改**」，「💾 保存设置」按钮由灰变亮。
4. **不点保存**，直接点左侧「**总览**」，再点回「**设置**」。
5. ✅ 「模型名称」恢复成原值、底部显示「无未保存修改」（现状即丢弃——若你希望保留，另提需求）。
6. 再改一次「模型名称」，然后点「**放弃修改**」。
7. ✅ 页面刷新，字段回到已保存值。

## R6 找不到核心：红条 + 手填路径恢复（对应 G13）

> 原理：把 `vision-relay.exe` 临时改名，GUI 启动后就“找不到核心”。

1. **管理员身份**打开一个 Git Bash（开始菜单搜 Git Bash → 右键 → 以管理员身份运行），粘贴（第一行先确认你的实际路径）：

```bash
where vision-relay          # 看输出的路径，下面命令按你的实际路径改
ren "D:\Program Files\Python314\Scripts\vision-relay.exe" vision-relay.exe.hidden
```

（如果 `ren` 报“拒绝访问”，说明该目录需要更高权限——右键用管理员重开再试；仍不行就用文末“方法 B”。）

2. 关掉 GUI（托盘退出），重新 `pnpm tauri dev` 启动。
3. ✅ 页面顶部出现红色横条「**核心不可用：… 找不到 vision-relay 核心**」。
4. 「设置」→「外观」→「核心路径」填入改名后的完整路径（例如 `D:\Program Files\Python314\Scripts\vision-relay.exe.hidden`）→ 点「💾 保存设置」。
5. ✅ 几秒内顶部红条消失、总览恢复数据（手填路径生效）。
6. **恢复环境**（必做）：管理员 Git Bash 粘贴：

```bash
ren "D:\Program Files\Python314\Scripts\vision-relay.exe.hidden" vision-relay.exe
```

7. 重启 GUI（托盘退出 → `pnpm tauri dev`），✅ 一切恢复正常（手填路径只存在内存里，重启自动重新探测 PATH）。

> **方法 B（不想改系统文件时）**：用 PowerShell 启动一个“看不见 vision-relay”的 GUI：
> ```powershell
> cd E:\LLMproject\Github\vision-relay\gui
> $env:Path = "$env:APPDATA\npm;C:\Windows\System32"
> pnpm tauri dev
> ```
> （若报 pnpm 找不到：先 `where.exe pnpm`，把其所在目录加进 `$env:Path` 再试。）测试完成后关闭该窗口、按 0.2 正常重启即可。

## R10 真 VLM 发图过代理 → 识图记录三段（对应 M1 手册 A5）

> 前置：路由开关开（绿点）；设置页 VLM 已配好真实 key；R9 已把模型能力标注跑过（保持默认“按纯文本走识图”即可）。

1. 新建文件 `payload.json`（放桌面即可），内容如下——**把 `模型名` 换成你真实的纯文本模型名**，其余原样：

```json
{
  "model": "模型名",
  "messages": [
    {"role": "user", "content": [
      {"type": "text", "text": "这张图片是什么颜色？"},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,iVBORw0KGgoAAAABAAA…"}}
    ]}
  ]
}
```

⚠️ 注意：上面 base64 中间的 `…` 是占位——请使用下面这一整串替换掉 `iVBORw0KGgoAAAABAAA…`（含引号内全部内容）：

```
iVBORw0KGgoAAAANSUhEUgAAAAgAAAAICAIAAABLbSncAAAAEklEQVR4nGP4z8CAFWEXHbQSACj/P8Fu7N9hAAAAAElFTkSuQmCC
```

（这是一张 8×8 纯红色小图，正确答案 = 红色。）

2. Git Bash 粘贴（把路径换成你放 payload.json 的位置）：

```bash
cd /c/Users/<你的用户名>/Desktop
curl.exe http://127.0.0.1:8787/v1/chat/completions -H "Content-Type: application/json" --data @payload.json
```

3. ✅ 返回一段 JSON，`content` 里是对颜色的回答（如“红色”）——图片被 VLM 转述注入后上游答对了。
4. GUI 左侧「**识图记录**」页：
   - ✅ 左侧树出现 harness 分组，无会话标识的归「**未识别会话**」。
   - ✅ 点最新一条记录，右侧三段齐全：**① 发给 VLM 的提示词**（蓝）→ **② VLM 原始返回**（紫，含“红”）→ **③ 实际注入对话的文本**（绿，以「**[图片描述]**」开头）。
