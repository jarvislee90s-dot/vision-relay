## 1. 背景与动机

vision-relay 已接管 claude-code、codex、qwen-code 三个编码工具的识图路由。用户日常工作流中新增了第四个工具 **zcode**（智谱桌面编码客户端），它同样存在「纯文本模型挡图片」的问题，需要纳入同一套「代理转写图片为文字描述」的安全网。

zcode 与前三个工具有三点本质差异，决定了它不能简单照抄任何一个的接入方式：

1. **没有中间路由工具**：zcode 不经过 CC Switch / Codex++，拓扑上与 qwen-code 同类——路由关闭 = 直连上游，路由开启 = 请求先进本代理。永远一层直连。
2. **供应商配置在桌面客户端自己的配置文件里**（`~/.zcode/v2/config.json`），且**多个供应商并列共存、单选激活**（同一时刻只有一个供应商处于启用状态）；每个供应商自带地址、密钥和一份模型清单。
3. **配置文件对外部修改不热加载**（用户实测，2026-08-26）：从外部改文件，运行中的 zcode 客户端不受影响，**重启后才生效**；而在 zcode 客户端内部做的修改会立即生效并写回文件。这与前三个 CLI 工具「每次启动读配置」的模型不同，引入了「重启生效」这个新交互维度。

同期暴露的普遍问题：工具数量从 3 涨到 4 后，「路由开给谁」需要成为用户可勾选的选项，而不是全量绑定。

## 3. 术语与全局决策

- **harness 名**：`zcode`。与前三个工具并列进入「受管工具」清单（总览、模型能力、设置、快照、对账全部按同一套机制对待）。
- **永远一层直连**：zcode 没有第二跳工具。转发链路恒为「zcode → 本代理 → 真实上游」，不存在两层拓扑与工具回落话题。
- **「重启生效」为 zcode 特有交互**：本代理改的是文件，运行中的 zcode 要**重启后**才按新文件行事。所有改写 zcode 配置的动作之后，只要检测到 zcode 正在运行，就要提示用户重启（并提供一键重启，见 §7）。
- **快照不存密钥值**（沿用仓库铁律）：zcode 的接管记录只存地址原值与模态门原值，绝不存密钥明文。
- **密钥指纹例外**：转发条目上允许存密钥的**非可逆缩略指纹**（前 4 位 + 后 4 位 + 长度，如 `963b…9NVz@36`）用于选路消歧。8 个字符无法还原 32+ 字符的随机密钥，且 proxy.json 本就 0600 存有完整密钥的转发条目——指纹严格更不敏感；指纹不进日志、不进 GUI。
- **模态门与 zcode 自身簿记联动**：补图片准入时，同时把该模型的「模态已手动配置」标志置位，防止 zcode 在某些时机把未标记的模型模态重置回去；原值一并记录、还原时回写。

## 4. zcode 配置形态（事实描述）

`~/.zcode/v2/config.json`（Windows 实测；macOS/Linux 路径假定相同，见 §10 残余风险）关键结构：

- `provider.<供应商ID>` 并列多个供应商；供应商 ID 形如 `builtin:bigmodel`（预置）或 UUID（用户自建），文件内唯一。
- 每个供应商：显示名、**接口格式 kind**（`anthropic` / `openai` / `openai-compatible` 三种）、`options.baseURL`（上游地址）、`options.apiKey`（密钥）、`enabled`（是否激活，**单选**）、`models`（模型清单）。
- 密钥为空串 = 预置供应商但未实际配置（常伴随 `enabled:false` 与系统禁用原因）——**这类供应商既不可用也不该被接管**。
- 每个模型条目：显示名（条目键，如 `GLM-5.3`）、可选的 `name`（真正的 API 模型名，如 `glm-5-turbo`；缺省时显示名即 API 名）、`modalities.input`（输入模态清单——纯文本模型只有 `["text"]`，多模态含 `"image"`）、zcode 自身簿记（`modified`、`modalitiesConfigured`、`deletedModels` 等）。
- 同一模型名可能出现在多个供应商名下（如 `GLM-5.3` 同时在两家）——这是选路消歧问题的根源（§6）。

**接口格式与转发协议的对应**：`anthropic` → 本代理的 anthropic 协议；`openai` / `openai-compatible` → chat 协议。其他未知格式不接管、计数透出。

## 5. 接管与还原（路由开/关时对 zcode 做什么）

### 5.1 开启路由（接管）

对配置文件里**每个供应商**依次判断，满足全部三条才算「可接管」：

1. 上游地址非空；
2. **密钥非空**（空密钥的预置供应商：地址不动、模型门不动、计入「跳过-未配密钥」——它们本来就用不了，改了反而制造假状态）；
3. 接口格式是本代理认识的三种之一。

对每个可接管的供应商：

- **记原值**：把「供应商 ID + 接口格式」作为身份键，记下它的原始地址。身份键带上接口格式的理由：若 zcode 某次更新把某供应商从 anthropic 换成了 openai 类（默认地址也换了），还原时不认这个键 → 不盲目写回旧地址，交给对账把新地址当「用户换了上游」吸收（与既有吸收语义一致）。
- **改地址**：上游地址 → 本代理（`http://127.0.0.1:8787`）。已经指向本代理的不重复记录（幂等，防止把代理地址存成「原值」）。
- **开门**：对该供应商**每个**纯文本模型（`modalities.input` 不含 `"image"` 的），在输入模态里补上 `"image"`，同时置位「模态已手动配置」标志。原值（原本的模态清单、原本的标志值，含「原本没有该字段」的情形）都记入接管记录。**只有被接管的供应商才开门**——空密钥供应商的请求不走本代理，给它们开门等于放图片直塞纯文本上游报错。
- 模态清单缺失或形态不认识的模型不硬造，计数透出（实际配置未见此形态，残余风险见 §10）。

改写前先做整文件备份（沿用既有「第一次接管前的原始文件」备份惯例，已存在则不覆盖）；改写用原子写；接管组合（地址原值映射 + 模态门原值映射 + 激活供应商的原始地址 + 密钥所在位置描述）记入快照。**zcode 的接管记录里绝不出现密钥明文。**

### 5.2 关闭路由（还原）

- **守卫**：只有当前地址仍指向本代理的供应商才动——用户在 zcode 里已把某家改走别处的，原样保留。
- **认人**：按现场重算「供应商 ID + 接口格式」身份键，在接管记录里找原值；找不到（身份变了/记录没了）→ 跳过该供应商，交给对账吸收。
- **回写**：地址写回原值；模态门对称还原——把本代理补的那个 `"image"` 移除（记录说原本没有模态清单就连字段一起删），「模态已手动配置」标志按原值回写（原本没有该标志就删）。
- 优先按快照做外科手术式还原（保留 zcode 运行期的其他改动）；快照缺失时退回整文件备份兜底——与前三个工具同一套取舍。
- **停用与取消勾选共用同一条还原路径**：从「停止服务时的全量还原」里抽出单工具粒度的还原步骤，「路由范围里取消勾选 zcode」（§8）复用它，只还原 zcode 一家。

### 5.3 幂等与防污染

重复接管不产生新记录（已就位的不动）；对账期间重打补丁同样幂等。这与既有机制完全一致。

## 6. 转发与选路（路由开启后请求怎么走）

路由开启后，zcode 所有可接管供应商的地址都指向本代理。本代理收到请求时只知道「协议 + 模型名 + 客户端密钥头」——**「请求本意走哪家供应商」这个信息在网络层已丢失**，需要推断：

1. **按密钥指纹精确认家（主路径）**：接管/对账时，每个供应商生成一条专属转发条目（指回它的原始上游、密钥透传客户端头——沿用 qwen 一层直连的模式），条目上带该供应商密钥的缩略指纹。请求到达时，从客户端密钥头算出同样的指纹，**指纹对上哪家就走哪家**——零窗口、完全准确，供应商切换即时生效，无需等对账。
   - 指纹歧义（两家共用同一密钥）或请求不带密钥头 → 走第 2 层。
2. **激活供应商优先（兜底）**：zcode 的 `enabled` 单选激活。维护 zcode 转发条目时，把当前激活供应商的条目排在最前——同名模型按顺序命中时激活家赢。用户在 zcode 里切换供应商后，下一次对账（刷新/自动对账）重排序；切换到对账之间的短窗口内，同名冲突模型可能带新家密钥走到旧家上游，结果是可见的 401（不会静默计费错家），刷新即修复。M3 的 5 秒自动对账上线后窗口自动缩小。
3. **模型双名收录**：每个模型的显示名与 API 名**都**进转发条目的匹配表（如 `GLM-5-Turbo` 与 `glm-5-turbo` 都列上）——不对 zcode 请求体里用哪个名字作猜测，两种都能命中。
4. **能力标注键一致**：zcode 转发条目携带「供应商身份」；请求期模型能力判定用的供应商键 = 矩阵标注用的供应商键 = 供应商 ID——两侧天然同键，标注不会因键不一致而失联。

转发条目的生命周期与 qwen 模式相同：接管时自动创建、对账发现缺失即重建、原始地址从接管记录消失即清理、停止路由随自动条目一并撤销。原始地址指向本代理或已知工具端口的组不建（防回环）。

密钥指纹机制做成通用件：任何转发条目都可以带指纹、选路时统一优先精确指纹命中——qwen 未来接入同机制只需在建条目时补指纹（本 spec 记为可扩展点，不在本期范围）。

## 7. 对账与重启提示

### 7.1 漂移收敛

zcode 纳入既有对账引擎，单分支处理（比 qwen 更简单——zcode 纯条目级，没有全局地址概念）：服务运行中且 zcode 在受管清单内时，每次对账都做一遍幂等检查——

- 有供应商地址被改走（用户换上游/新增供应商）→ 重新接管并把**新地址吸收**进接管记录（吸收语义，GUI 告知「检测到上游变化，已接管」）；
- 模态门被关（zcode 运行期用内存旧值回写文件，见 §1 差异 3）→ 重开；
- 转发条目缺失/过期 → 重建/清理。

无漂移不碰文件（幂等铁律）。

### 7.2 重启提示（zcode 特有）

**触发**：任何改写了 zcode 配置文件的动作（接管、还原、取消勾选、对账重打补丁）之后，检测 zcode 进程是否在运行（平台进程枚举，尽力而为）。

**呈现**：总览页出现提示条「zcode 需重启生效」，附**「立即重启 zcode」按钮**（结束进程 + 按探测到的程序路径分离重启；重启失败退化为纯提示，不阻塞任何流程）。重启动作记入事件日志。

**自动重启开关**：设置页提供「接管/还原后自动重启 zcode」选项，**默认关闭**——自动重启可能中断 zcode 里进行中的任务，默认交给人；开启后上述场景不再等用户点按钮，改写完成即自动重启。

### 7.3 状态口径

- 归属判定：激活供应商的当前地址。
- 「已接管」的达标线：**所有**可接管供应商的地址都指向本代理**且**模态门全开（与 qwen 口径一致——门没开图片进不了请求，地址对了也不算真接管）。
- 状态页为 zcode 附供应商统计：总数 / 可接管数 / 已接线数 / 门已开数 / 跳过数（含未配密钥）。

## 8. 路由范围勾选（全部四个工具）

**动机**：工具多了以后，「路由开给谁」应可勾选；取消勾选的工具在界面上整体隐身，避免无关信息干扰。

**机制**：勾选状态就是既有「受管工具清单」（此前是隐含全量、无编辑入口）。设置页新增「路由范围」区块：claude / codex / qwen-code / zcode 四个勾选框，保存即生效。

**取消勾选的即时语义（关键决策）**：**取消即还原**——保存时若路由正开着且该工具当前处于接管态，立即对它执行单工具还原（§5.2 抽出的共用路径），然后从清单移除；路由关着时取消 = 纯隐藏。这样杜绝「从清单移除后，停止服务时的全量还原不再覆盖它 → 断头接管静默残留」的缺口。取消勾选 zcode 同样触发重启提示（§7.2）。

**隐藏范围（全量扫描结论）**：取消勾选后，该工具的——总览拓扑卡、模型能力页供应商×模型行、批量实测候选、设置页 VLM 分组、首次向导标注行——全部不再出现（这些页面本就按受管清单迭代，后端天然成立；设置页 VLM 分组当前是硬编码清单，改为派生）。它名下残留的历史标注、VLM 覆盖配置**不清理**（无害，重新勾选即恢复可见）。

**存量配置迁移**：已有用户的受管清单是显式存档的三工具全集。规则：恰好等于旧默认全集 → 升级为含 zcode 的四工具全集；不等于（说明用户曾显式排除过某工具）→ 视为有意选择，不自动加 zcode，由用户自行勾选。

## 9. 扫描、实测与模型能力

- **供应商×模型矩阵**：zcode 的矩阵直接读它自己的配置文件——每家可接管供应商一行（供应商名 = 供应商 ID，唯一可反查），`enabled` 即「当前激活」，模型列 API 模型名。**空密钥供应商整行不产**：不进矩阵、不进扫描、不进「探测全部未测」的候选（需求 Z2）。不走直连兜底——zcode 的矩阵真相就是它自己的配置文件，文件不存在则空矩阵。
- **模态实测（探针）**：复用既有「纯接收判定」探针。zcode 的探测目标 = 该供应商的原始上游地址（现场值若已指向本代理则取接管记录里的原值）+ 该供应商自己的密钥（仅进程内使用，不进日志/输出）+ 按接口格式确定的协议。
- **能力标注**：三元组 (zcode, 供应商 ID, 模型 API 名) 存储，取值优先级、目录建议、内置名单（`glm/*` 纯文本、`kimi-k2.7-code*` 支持图片等）全部沿用，zcode 模型天然命中。
- **拉取模型清单**：沿用既有行为（回环不拉、失败带原因）。

## 10. 风险与残余

| 级别 | 事项 | 说明与对策 |
|---|---|---|
| P1 | zcode 运行期冲补丁 | 客户端内保存会用内存旧值回写文件，改掉本代理的接线与模态门。对策：对账重打补丁（§7.1）+ 重启提示（§7.2）；**生效仍等 zcode 重启**——提示条覆盖 |
| P1 | 重启前的断头窗口 | 路由关闭后运行中的 zcode 内存里仍是本代理地址，代理已停 → 请求失败。对策：关闭路由同样触发重启提示 |
| P1 | 同名模型错家 | 无指纹场景（同密钥两家/无密钥头）回落顺序命中，切换窗口内可能 401。可见、可刷新修复、M3 自动对账后窗口 ≤5s |
| P2 | 跨平台路径 | `~/.zcode/v2/config.json` 仅 Windows 实测；macOS/Linux 假定同路径，实机验证随 M3 打包回归补 |
| P2 | 请求体模型名形态 | 双名收录缓解；若 zcode 用第三种形态 → 仅按协议兜底命中（可能错家，401 可见） |
| P2 | 模态清单形态异常 | `modalities.input` 缺失/非列表的模型不补门（计数透出），图片仍被 zcode 内部拦截——现有配置未见此形态 |
| P2 | 指纹碰撞 | 同密钥多家供应商 → 指纹歧义回落顺序命中（§6.2） |

## 11. 测试与验收

- **单元/集成测试**（沿用既有测试文件归置惯例）：接管准入（空密钥/未知格式跳过）、地址改写与身份键记录、模态门与标志的补丁/哨兵还原/幂等、守卫还原（身份变更不命中、用户改走不动）、单工具还原复用（停止全量 vs 取消单个）、转发条目一供应商一条 + 双名 + 清理 + 激活优先、密钥指纹形态与三层选路优先级、矩阵空密钥不产行、存量清单迁移两种走向、取消勾选触发还原。
- **端到端**：伪造 zcode 配置文件的固定场景，接管 → 选路（指纹命中/回落）→ 还原全链路。
- **门禁**：全量 pytest、ruff format --check、ruff check。
- **手工验收（Windows 真机）剧本**：
  1. 勾选 zcode → 开路由 → 提示重启 → 一键重启 zcode → 纯文本模型读图得到转写（识图记录可查）；
  2. 多模态模型（kimi 类）读图直通不转写；
  3. 空密钥预置供应商：地址与模型门全程未动、不出现在模型能力页；
  4. zcode 客户端内切换供应商 → 刷新对账 → 请求按新家走（指纹选路）；
  5. 路由开启期间在 zcode 内部改任意设置（触发文件回写）→ 刷新对账 → 补丁重打、状态恢复「已接管」；
  6. 关路由 → zcode 配置回到原值（地址、模态门、标志逐项比对）→ 提示重启；
  7. 设置页取消勾选 zcode（路由开着）→ zcode 立即回直连 + 相关界面整体隐身；重新勾选恢复；
  8. claude/codex/qwen-code 三工具全流程回归不受影响。

## 12. 明确不做（本期范围外）

- qwen 转发条目接入密钥指纹机制（选路通用件已就位，qwen 补指纹属增量优化，另期）；
- zcode 供应商的密钥轮换检测专项（对账重建转发条目时自然跟随文件新值）;
- 在 zcode 客户端内部模拟人工操作改配置（UI 自动化方案已否决：脆弱、不可批量、无法与快照体系对接）；
- 视频/音频模态（沿主 spec 三期边界）；
- macOS/Linux 实机验收（随 M3 打包回归）。

## 13. 决策记录（2026-08-26 与用户逐条确认）

| 决策点 | 结论 |
|---|---|
| 整体方案 | 沿既有模式扩展（镜像 qwen 条目级接管成套机制），不做统一条目型框架重构、不旁路对账体系 |
| 拓扑 | 永远一层直连，不经过 CC Switch / Codex++ |
| 快照身份键 | 供应商 ID + 接口格式组合键（还原侧强身份校验；格式变更→不还原→对账吸收新值） |
| 快照与密钥 | 沿用「快照绝不存密钥值」铁律；密钥指纹（前4+后4+长度）作为唯一例外存于转发条目，不进快照/日志/GUI |
| 空密钥供应商 | 不接管、不开门、不进扫描与实测，计数透出 |
| 模态门 | 路由开启给纯文本模型补 `image` 准入，**同时置位 zcode 的「模态已手动配置」标志**（防重置）；原值记录、关路由对称还原 |
| zcode 配置热加载行为 | 用户实测：外部改动需重启生效、客户端内改动即时生效并回写文件——据此设计重启提示与对账重打补丁 |
| 重启交互 | 提示条 + 「立即重启」按钮；「自动重启」为设置项且默认关闭（防中断进行中任务） |
| 选路消歧 | 密钥指纹精确认家为主，激活供应商条目排序优先为兜底，模型双名收录 |
| 取消勾选语义 | 取消即还原（复用停止路由的单工具还原路径），杜绝断头接管静默残留 |
| 路由范围数据结构 | 复用既有「受管工具清单」，不新造配置项；旧默认全集自动升级、显式排除不自动加 |
| GUI 适配 | zcode 与前三工具同规格（拓扑卡/模型行/VLM 分组/向导行自动跟随）；VLM 分组清单从硬编码改为派生 |
