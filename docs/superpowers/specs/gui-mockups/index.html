📌 设计要点与决策点
①自动决策原则（本设计的骨架）：每个面向用户的交互过三问——能从已记录状态/规则推导 → 系统自动做，零感知；推导不出但有安全默认 → 默认自动 + 被动通知可改；需要用户资源或真实意图 → 才暴露给用户。铁律：自动化之后可见性补位——每个自动动作在总览「自动处理」区与事件日志留痕，用户不决策但能核查。
②用户决策点只有 6 个：①路由总开关 ②首次填 VLM（key/模型/端点，账号资源）②b 首次过目模型能力（实测结果已就绪，改猜错的即可，可跳过）③缺 key 时补填（被动提示后才出现）④关闭 GUI 时选「仅关界面 / 连服务一起关」（问一次并记住）⑤停用某条转发（稀有，藏在详情）。其余全部自动或被动。
③看编分离：监控类页面只看 + 少数动作；编辑集中在「设置」与「模型能力」。导航 5 页里识图记录 / 事件日志是纯看板——看不需要决策，可视化不是负担。总览的转发与工具信息并入每张 harness 卡的「详情」抽屉（快照 / relay / 停用），不设独立区块。
④模型能力 = (harness, provider, 模型) 三元组：同一模型名经不同 provider 能力可能不同。provider 自动来自工具档案（两层 = 路由工具激活供应商）/ 接管快照（一层 = 直连上游），用户不用填。记录只存输入模态一个字段、三态（纯文本 / 支持图片 / 未标注）；取值优先级：用户覆盖 > 实测探测 > 目录建议 > 未标注（空），上下文长度/推理档位不采集。
⑤模态探测（可验证探针）：对每个 (provider, 模型) 发一次最小带图请求——图里藏一个字，问"图里是什么"。三档判定：报错（不支持图片输入）→ 纯文本；答对 → 支持图片；返回 200 但答错（静默吞图）→ 纯文本。超时 / 401 / 404 / 5xx 不下结论，回落目录建议（models.dev 风格外部目录，只取其输入模态字段）。成本每模型一次最小调用，结果缓存可重测。空状态（未标注）的运行行为 = 设置里的全局开关：默认「按纯文本走 VLM 转述」=安全侧；可切「直通」省 token 但真纯文本会报错——开关两侧的代价就是界面文案。视频/音频模态探测留三期。
⑥其他定稿：保存语义统一（输入类控件一律页底统一保存，仅按钮类动作即时）；语言选择可见（跟随系统/中文/English）；托盘纯文字菜单（状态行 · 打开主界面 · 路由开/关 · 诊断报告 · 退出停止服务）；模态术语统一「图片 / 纯文本」。
