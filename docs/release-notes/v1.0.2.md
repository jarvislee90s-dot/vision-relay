## 🔧 修了什么

**① 安装包「开启路由」无法启动（必更）**

v1.0.0 / v1.0.1 的安装包里，点总览的「开启路由」后服务进程会静默死亡——分离启动子进程的命令行带了一个在打包环境下非法的参数，被拒后直接退出：不写 pid、不改写任何工具配置、代理端口永不监听，开关看起来毫无反应（旁边那句「自动对账中」是写死的装饰文案，不是卡在对账，本版也换成了真实的接线开关状态）。崩溃自愈自动重启同样失效。**源码 / pip 方式运行不受影响**——这是打包环境特有的缺陷，也是它漏过测试的原因（真机安装验收此前未执行）。

**② cc-switch 两层转接偶发 401 / 502**

历史上「吸收直连」遗留的 `direct-*` 中继没有密钥指纹钉死，会在选路时排在真正的工具中继前面截胡流量——带着 cc-switch 的会话 token 直连旧上游被拒。本版对账会在确认两跳接线（快照记录了经由 cc-switch / Codex++）时自动清理此类遗留中继，配置热加载即时生效。若遇到同类问题，详情抽屉里的「停用转发」按钮现在也可用于 `direct-*` 中继手动止血。

**③ 设置页取消勾选 zcode 不生效**

取消勾选 zcode 并保存后，重进设置页发现它又被勾上了——旧配置迁移逻辑每次读配置都会把 zcode 加回（取消 qwen 却正常，因为存盘内容恰好躲开了误判条件）。已改为一次性迁移。

**④ 其余修复**

- 总览 zcode 卡曾显示 relay「已旁路」而实际请求在正常走中继（zcode 自己会改写配置文件造成磁盘显示偏差），现按条目级真实接线状态显示；
- 「direct-claude 直连上游缺 API key」误报消除：直连中继本来就不存密钥（认证透传），只要你的 harness 配置里密钥位置真实存在就不再提醒；
- 模型能力页不再把 claude 的展示名字段（`*_MODEL_NAME`）当成独立模型（此前 `GLM-5.3[1M]` 和 `GLM-5.3` 会显示成两个）；
- 模型探测完成后「当前标注」即时更新（此前要切走页面再回来才能看到结果）。

**⑤ 体验优化**

- 「探测全部未测」进行中可随时「⏹ 终止探测」；且只测真正未测的模型——你手动标注过或已有实测结论的不再重复探测；
- 总览详情抽屉的中继列表按所属工具过滤，不再每个工具下面都出现全部中继和停用按钮；`direct-*` 标注「直连透传」以示区分。

> 排查说明：本批问题经新旧代码逐行比对与真机复现确认**全部为存量缺陷**，与 v1.0.1 的模块化重构无关；证据链见 [修复设计稿](https://github.com/jarvislee90s-dot/vision-relay/blob/main/docs/superpowers/specs/2026-09-02-post-refactor-regression-fixes-design.md)。v1.0.1 草稿发布作废，由本版取代。

## ⬇️ 下载安装包

**不需要 Python 环境**（核心已内嵌）。Windows / Linux 装完即用；**macOS 首次打开需一步操作，见表格下方**。

| 平台 | 安装包 | 说明 |
|---|---|---|
| 🪟 Windows 10/11 · x64 | `vision-relay-1.0.2-win-x64-setup.exe` | 常规安装向导 |
| 🍎 macOS · Apple Silicon | `vision-relay-1.0.2-macos-arm64.dmg` | 拖入「应用程序」即可；Intel Mac 暂不支持 |
| 🐧 Linux · x64 | `vision-relay-1.0.2-linux-x64.AppImage` / `.deb` | AppImage 免安装，deb 适用于 Debian/Ubuntu 系 |

完整性校验：把 [SHA256SUMS.txt](https://github.com/jarvislee90s-dot/vision-relay/releases/download/v1.0.2/SHA256SUMS.txt) 下载到与安装包相同的目录，在下载目录内执行 `shasum -a 256 -c SHA256SUMS.txt`（Windows 可用 `certutil -hashfile <文件> SHA256` 逐个比对）。

### 🍎 macOS 首次打开（重要）

把应用拖入「应用程序」后双击，macOS 可能弹「"vision-relay"已损坏，建议移到废纸篓」——**文件没有损坏**（可先按上法核对 SHA256）：这是 Gatekeeper 对「网络下载 + 无 Apple 公证签名」应用的统一措辞。本应用暂未购买 Apple 开发者计划（$99/年），以 ad-hoc 签名分发。在「终端」执行一条命令移除隔离标记，之后正常打开：

```bash
xattr -cr /Applications/vision-relay.app
```

（每次新版本安装后需再执行一次。）后续配置 Apple 公证后，此步骤将取消。

> 无界面 / 服务器场景也可以走命令行：`pip install vision-relay`（Python 3.10–3.13），用法见 [README](https://github.com/jarvislee90s-dot/vision-relay/blob/main/README.zh.md)。

## 📝 已知限制（同 v1.0.0）

- macOS 包为 Apple Silicon 原生；Intel Mac 暂不支持（原生 universal 包随后续版本提供）。
- qwen-code 的接线在会话启动时加载：已开的 qwen 会话需重启后才会走代理。
- 两个应用同时想改同一份工具配置时，vision-relay 会在总览页提示并可一键抢回——不建议让多工具混改。
